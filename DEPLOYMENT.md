# Deploying to cPanel

## The one rule

**The project must live outside `public_html`.**

cPanel's Application Manager expects two separate directories:

| | Path | Contents |
| --- | --- | --- |
| Application root | `/home/USER/symtera-web` | the whole project |
| Document root | `/home/USER/public_html` | one generated `.htaccess`, plus any folders you add yourself |

Putting the project inside `public_html` breaks the site and exposes the source.
Apache serves any URL that matches a real file on disk before Passenger ever
sees the request, so `/package.json`, `/server.js`, `/README.md`,
`/node_modules/...` and the whole of `.next/` become publicly downloadable,
while `/_next/static/...` returns 500 because that URL prefix does not match the
on-disk `.next/static` path. The visible symptoms are a site with no stylesheet,
which shows as a white border around everything and serif type, plus broken
images and 500s on every route except `/`.

## Correct layout

```
/home/USER/
├── symtera-web/          ← Application root
│   ├── .next/            ← created by `npm run build` on the server
│   ├── app/  components/  content/  lib/  public/
│   ├── node_modules/
│   ├── server.js         ← Passenger startup file
│   ├── app.js            ← shim, for the panel's default startup-file value
│   └── package.json
└── public_html/
    ├── .htaccess         ← generated by Application Manager
    └── abc/              ← optional: served at /abc, see below
```

## Steps

1. Upload the project to `/home/USER/symtera-web`. Exclude `node_modules` and
   `.next`; both are rebuilt on the server.
2. In cPanel open **Setup Node.js App** and create the application:

   | Field | Value |
   | --- | --- |
   | Node.js version | 20 or newer |
   | Application mode | Production |
   | Application root | `symtera-web` |
   | Application URL | the domain, with no subfolder |
   | Application startup file | `server.js` |

3. Add the environment variables in that same screen, not in a `.env` file,
   because Passenger does not read one. See **Email** below for which ones.
4. Click **Run NPM Install**, then open the terminal it offers and run the
   build. Raise the heap first if the plan is memory constrained:

   ```bash
   source /home/USER/nodevenv/symtera-web/20/bin/activate
   cd ~/symtera-web
   NODE_OPTIONS=--max-old-space-size=2048 npm run build
   ```

5. Click **Restart**.

## Verify

```bash
curl -I https://your-domain/                       # 200, X-Powered-By names Passenger
curl -I https://your-domain/about                  # 200
curl -o /dev/null -w '%{http_code}\n' https://your-domain/package.json   # must be 404
```

That last check is the important one. A 200 means the project is still in the
web root and the source is public.

## Fixing a site already deployed into `public_html`

```bash
cd ~
mkdir -p symtera-web
shopt -s dotglob
mv public_html/* symtera-web/
shopt -u dotglob
rm -f symtera-web/.htaccess          # the Passenger .htaccess belongs to public_html
```

Then point the application root at `symtera-web` in Application Manager and hit
Stop and Start, which regenerates `public_html/.htaccess` with the right
Passenger block. Rotate the mail credentials afterwards, since the deployment
directory was publicly readable.

## Permissions

Passenger refuses to run an app whose root is group or world writable, and
Apache reports that as a 403 rather than explaining it.

```bash
cd ~/symtera-web
find . -type d -not -path "./node_modules/*" -exec chmod 755 {} \;
find . -type f -not -path "./node_modules/*" -exec chmod 644 {} \;
```

Leave the home directory at cPanel's default of 711. Everything must be owned by
the cPanel user, never root.

## One hostname, over HTTPS

Four hostnames currently answer with the full site, and none of them redirects to
another:

```
https://symteratech.com/       200
http://symteratech.com/        200   ← plaintext
https://www.symteratech.com/   200
https://new.symteratech.com/   200   ← a second, older deployment
```

Every page carries a canonical tag pointing at the apex, which is why this has
not already split the index, but a canonical is a hint and a redirect is not.
The `new` subdomain is the sharper problem: it is a separate build, not a proxy
of the live one — its sitemap is stamped twenty minutes earlier than the apex's —
and it serves `index, follow`, so it is a crawlable copy that will drift. (The
two were originally told apart by their sitemap timestamps; now that `lastmod`
is a fixed constant, compare the build hash under `/_next/static/chunks/`
instead.)

Fix the apex and www in `public_html/.htaccess`, above the `# DO NOT REMOVE`
markers and above the folder rules in the next section, so that a folder request
is canonicalised too:

```apache
RewriteEngine On

# One scheme, one host. The two TLS conditions are AND-ed, so a proxy that
# terminates TLS and forwards over http does not send the site into a loop.
RewriteCond %{HTTPS} !=on
RewriteCond %{HTTP:X-Forwarded-Proto} !=https
RewriteRule ^ https://symteratech.com%{REQUEST_URI} [R=301,L,NE]

RewriteCond %{HTTP_HOST} !^symteratech\.com$ [NC]
RewriteRule ^ https://symteratech.com%{REQUEST_URI} [R=301,L,NE]

<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=300" "expr=%{HTTPS} == 'on'"
</IfModule>
```

`[NE]` stops Apache escaping the `%` in a path that is already percent-encoded,
which would otherwise turn `/our-partners/d%2Dlink` into a 404. The `Header`
line is guarded because an unrecognised directive in `.htaccess` is a 500 for
every request, not a warning, and `mod_headers` is not guaranteed on shared
hosting.

Two deliberate restraints on that header. It carries no `includeSubDomains`,
because that would also bind `webmail.symteratech.com`, which staff reach
through `/webmail`, and would lock it out of the browser entirely if it ever
answers on plain http. And `max-age` starts at 300 seconds rather than a year:
a browser that has seen a long HSTS header refuses to reach the site at all if
the certificate lapses, and as the next section explains, nobody has yet
established what renews this one. Raise it to 31536000 once a renewal has been
watched to completion.

`new.symteratech.com` is a different application with its own document root, so
that file does not reach it. Remove the subdomain in cPanel and delete its DNS
record. If it has to stay for testing, put the same redirect in its own
`.htaccess` — or at minimum serve `Header always set X-Robots-Tag "noindex"`
there, and remember that the canonical tag alone has never been enough.

Afterwards, each of these should answer `301` with `location: https://symteratech.com/...`:

```bash
for u in http://symteratech.com/ https://www.symteratech.com/ http://www.symteratech.com/about-us/; do
  curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" "$u"
done
```

## Two things to watch

**The certificate.** The live certificate is issued by Let's Encrypt and expires
19 November 2026 — a standard 90-day term. cPanel's own AutoSSL normally issues
Sectigo, so something else is renewing this one, either the cPanel Let's Encrypt
plugin or a certbot job. Find out which, because a cron job on a server that was
compromised in September is exactly the kind of thing that quietly stops running,
and an expiry takes the whole site down.

**`Cache-Control: s-maxage=31536000`.** Next sends that on every HTML page. It is
addressed to shared caches, and today nothing in front of the origin reads it —
Apache serves directly, and Next honours its own 300-second stale time. The day a
CDN is put in front of this origin, every page freezes for a year. Set a short
`s-maxage` at the edge before cutting traffic over.

## Extra folders alongside the app

A folder placed in `public_html` is served at the matching URL, so
`public_html/abc/` answers `https://symteratech.com/abc/`. Apache resolves a
request against the document root before Passenger sees it — the same behaviour
that made the source public when the project itself lived there, used
deliberately this time. Add as many folders as you like. They never reach the
Node app, so PHP works in them as well as static files, and nothing needs a
rebuild or a restart.

Each folder needs an index file, `index.html` or `index.php`, or Apache has
nothing to answer `/abc/` with.

Add this once to `public_html/.htaccess`, so that a folder without an index file
cannot list its contents to the world:

```apache
Options -Indexes
DirectoryIndex index.html index.htm index.php
```

Put it above the `# DO NOT REMOVE ... BEGIN` marker. Application Manager
rewrites everything between the markers each time the app is stopped and
started, and would take your lines with it.

Check a new folder with:

```bash
curl -sI https://symteratech.com/abc/ | head -1
```

A 200 means Apache served it. If the site's own 404 page comes back instead,
Passenger is claiming the URL first; turn it off for that folder with a
one-line `public_html/abc/.htaccess`:

```apache
PassengerEnabled off
```

To make that automatic for every folder you will ever add, put this in
`public_html/.htaccess` instead, again outside the markers:

```apache
<If "-d %{REQUEST_FILENAME} || -f %{REQUEST_FILENAME}">
  PassengerEnabled off
</If>
```

Two things to keep in mind. A folder shadows the site's own route of the same
name: `public_html/faq/` would hide `/faq`, and a name that matches a rule in
`lib/legacy-redirects.ts` beats the redirect. And these folders sit outside the
project, so `git pull` neither updates nor deletes them — back them up
yourself.

For static files only there is a second option: put the folder inside the
project's own `public/` directory. Next then serves `public/abc/report.pdf` at
`/abc/report.pdf` with no Apache configuration at all. It has no directory
index, so `/abc/` returns the 404 page and every file has to be requested by
name, and it cannot run PHP.

## Email

`/api/contact` has two transports and chooses between them at runtime: SMTP
whenever `SMTP_HOST` is set, the Resend API otherwise. Switching is a variable
change and a restart, never a rebuild.

**Through a cPanel mailbox.** Create `website@symteratech.com` in Email
Accounts, then set:

| Variable | Value |
| --- | --- |
| `SMTP_HOST` | `mail.symteratech.com` |
| `SMTP_PORT` | `465` |
| `SMTP_USER` | `website@symteratech.com` |
| `SMTP_PASSWORD` | that mailbox's password |
| `CONTACT_TO` | `sales@symteratech.com` |
| `CONTACT_FROM` | `Symtera Website <website@symteratech.com>` |

`CONTACT_FROM` has to be a mailbox that exists on the server; anything else is
rejected or lands in spam. If the connection fails on the certificate, the
server is presenting one for its own hostname: prefer putting that hostname in
`SMTP_HOST`, and use `SMTP_TLS_REJECT_UNAUTHORIZED=false` only if you cannot.

**Through Resend.** Verify the domain in Resend, add the DNS records it gives
you in Zone Editor, then set `RESEND_API_KEY`, `CONTACT_TO` and `CONTACT_FROM`,
and leave `SMTP_HOST` unset.

Set `SITE_URL` to the origin the site is actually served from as well: both
mails pull the logo from it, and a wrong value delivers a broken image.

Either way, test after restarting:

```bash
curl -s -X POST https://your-domain/api/contact   -H 'Content-Type: application/json'   -d '{"fullName":"Test User","email":"you@example.com","service":"AI Solutions","message":"transport check"}'
```

`{"ok":true}` means both the sales mail and the auto-reply were accepted. A 502
names the failing transport and the server's own error in `stderr.log`, and a
500 means neither transport is configured. The route allows 5 submissions per
IP per 10 minutes.

## Where errors go

Passenger writes startup and request failures to `stderr.log` in the application
root. With the correct layout this file is outside the web root and therefore
not public.

```bash
tail -50 ~/symtera-web/stderr.log
```

## The alternative: static export

This site is forty prerendered pages and one form endpoint. If Passenger keeps
causing trouble, switching `next.config.ts` to `output: 'export'` produces a
plain `out/` folder that drops straight into `public_html`, with no Node process
and no way to expose source, because only built output is uploaded. The trade is
that `app/api/contact/route.ts` has to be reimplemented as a PHP endpoint, since
static hosting cannot run a Route Handler.
